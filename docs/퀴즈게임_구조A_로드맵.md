# 🎯 나만의 퀴즈 게임 — 단계별 학습 로드맵 (구조 A · 책임 분리형)

> **구조 A**: `Quiz`(데이터) + `QuizBank`(보관·저장/불러오기) + `QuizGame`(메뉴·진행·점수)
>
> **목적**: 결과물이 아니라, 만드는 과정에서 과제 목표(Python 기초 · 클래스 · 파일 입출력 · Git)를 **스스로 설명할 수 있게 되는 것**. 여기에 더해 **"책임 분리(SRP)"** 감각까지 얻습니다.
>
> **진행 방식**: 각 단계마다 ①제가 코드를 작성·해설 → ②당신이 직접 실행해 확인 → ③Git 커밋. **한 단계 = 한 커밋.**

---

## 각 단계의 공통 구조 (design → develop → verify)

1. **🧠 이해할 것** — 이 단계가 채우는 과제 목표
2. **✍️ 설계 포인트** — 왜 이렇게 만드는지
3. **💻 개발** — 제가 코드 작성 + 한 줄씩 해설
4. **✅ 확인 & 커밋** — 직접 실행해 기대 출력 확인 → 커밋

끝의 **🧠 스스로 설명해보기**에서 막히면 그 부분이 아직 안 넘어간 것.

## Phase 4 · 구조 정리(책임 분리)와 영속성

### Step 9. `QuizBank`로 보관·저장 책임 분리 → 🔷 #10 ★
- **🧠**: **단일 책임 원칙(SRP)** / 캡슐화 / 클래스로 상태 감싸기
- **✍️**: 흩어진 데이터(퀴즈 목록·최고점수)와 그 관리 로직을 **`QuizBank`**로 모으고, 게임 진행은 **`QuizGame`**으로 정리. QuizGame은 `self.bank`를 통해 데이터에 접근
- **✅ & 커밋**: 동작 그대로, 구조만 또렷해지면 성공 → #10
- **🧠 스스로 설명**: "QuizBank와 QuizGame은 각각 무엇을 책임지나? best_score는 왜 QuizBank에, has_played는 왜 QuizGame에 두나?"

### Step 10. `state.json` 저장/불러오기 (QuizBank에) → 🔷 #11
- **🧠**: 파일 입출력 / JSON / `try/except` / 영속성
- **✍️**: `QuizBank.load/save`, `Quiz.to_dict/from_dict`. 파일 없음→기본, 손상→복구
- **✅**: 껐다 켜도 퀴즈·점수 유지되면 성공
- **🧠 스스로 설명**: "파일 읽고 쓰는 클래스를 QuizBank 하나로 못 박은 이유는?"

### Step 11. 안전 종료 → 🔷 #12
- **✍️**: `Ctrl+C`/EOF에도 안 죽고 `finally`에서 `bank.save()` 후 안전 종료
